# Stack sensitivity

<ApiFamilyHeader category="ICM" suit="♥" functions={["icmHarvilleStackJacobian"]} />

## `icmHarvilleStackJacobian` \{#icmHarvilleStackJacobian\}

`J[i * n + j]` = ∂(ICM EV of seat `i`) / ∂(stack `j`), by central differences with a step of about 6e-6 × stack `j` (two ICM evaluations per column). Columns sum to 0 (the prize pool is fixed) and `Σ_j stack_j × J[i * n + j] = 0` (ICM depends only on stack ratios). Stacks must be positive.

```ts
icmHarvilleStackJacobian(
  stacks: F64VectorInput,
  payouts: F64VectorInput,
  returnFormat?: F64ReturnFormat
): number[] | Float64Array;
```

You need **local sensitivity** of tournament dollars to small stack changes — for example bubble planning, deal-making sliders, or reporting which seat's stack moves matter most to a given player's ICM.

```js title="Example"
const poker = require('poker-calculations');

const stacks = [12000, 8000, 5000, 2000];
const payouts = [10000, 6000, 3000, 1000];

// Row-major n × n: entry i * n + k is ∂EV(seat i) / ∂(stack of seat k), in prize units per chip
const n = stacks.length;
const j = poker.icmHarvilleStackJacobian(stacks, payouts);
console.log('∂EV(hero)/∂(hero stack):', j[0 * n + 0].toFixed(4));
console.log('∂EV(hero)/∂(seat 2 stack):', j[0 * n + 2].toFixed(4));

const flat = poker.icmHarvilleStackJacobian(stacks, payouts, 'float64');
console.log(flat.length === stacks.length * stacks.length);

// Two players, winner takes 100: EV(seat 0) = 100a / (a + b), so ∂/∂a = 100b / (a + b)² = 25 at a = b = 1.
console.log(poker.icmHarvilleStackJacobian([1, 1], [100, 0]).map((x) => x.toFixed(2)));
```

```text title="Output"
∂EV(hero)/∂(hero stack): 0.1559
∂EV(hero)/∂(seat 2 stack): -0.1355
true
[ '25.00', '-25.00', '-25.00', '25.00' ]
```

This is a numerical approximation of the Harville model's derivatives. Each column `j` evaluates ICM at `stacks[j] ± h` with `h ≈ 6e-6 × stacks[j]` and divides the payout difference by `2h`, so the error is second order in `h` and the step scales with the stack. Before 4.2.0 it used a one-sided step of at least one chip, which was far too coarse for small stacks: `([1, 1], [100, 0])` gave ±16.67 instead of `[25, −25, −25, 25]`.

**Returns** a flat row-major `number[]` of length `n²` (entry `i × n + k` is ∂EV(seat i) / ∂stack(seat k)), or a `Float64Array` when `returnFormat` is `'float64'`.
